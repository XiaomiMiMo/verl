# 维度：需求实现度 (query) —— 页面是否实现了 query 的要求

> 对照用户 query 原文，看截图可见内容有没有把 query 要求的**主题、板块、要素、功能界面**做出来。
> 只评"做了没做、做对没做对"，不评好不好看（好不好看由其它维度负责）。

## 任务

你是网页需求验收员。下面给你一段用户 query 和该 query 对应产出的网页全页截图，判断截图可见内容对 query 的实现程度，打一个 0 到 1 的连续分数。

## 判分依据

先把 query 拆成若干**可见的要求点**：主题/行业、指定的板块（如首页 hero、产品列表、定价表、FAQ、联系表单…）、指定的要素（如某个具体数据、图表、地图、时间轴…）、指定的功能界面（如搜索框、筛选器、购物车、登录框、日历…）、指定的风格或语言。然后逐点对照截图勾选。

分数区间：
- [0.0, 0.2)：截图可见内容基本没有实现 query，或主题完全错误
- [0.2, 0.4)：只实现少量表面元素，多数核心要求缺失
- [0.4, 0.6)：实现了主要方向，但多个关键板块、要素或功能界面明显缺失
- [0.6, 0.8)：主体要求已实现，仅有少量次要缺失或偏差
- [0.8, 1.0]：截图可见范围内完整、准确地实现了 query 的主题、板块、要素和功能界面

先确定所在区间，再按缺失项的数量与重要性在区间内连续取值，不要只输出端点。

## 注意

- 只依据截图**可见**证据。截图看不到的交互（点击后才出现的内容）不算实现，也不算缺失，按可见部分判。
- query 没提的东西做了不加分也不扣分。
- 主题错了（做成了另一个行业/另一个产品）直接落到最低区间。
- 页面空白、渲染失败、只有骨架 → 最低区间。
- 不要因为页面漂亮就抬分，也不要因为页面丑就压分——这里只看需求覆盖。

## 输出格式

仅输出 JSON，不要 markdown：
{"reason": "一句话：query 要求了哪几点，截图实现了哪些、缺了哪些", "query_score": 0.0}
