# 组内挑选（group pick）—— 挑出明显更好的与明显更差的，其余不排

> 一次调用看同一 query 的全部 rollout 截图（编号随机）。任务不是排全序，而是：
> 挑出**明显优于其他**的若干张（0 到多张）、**明显差于其他**的若干张（0 到多张）；
> 其余视为"一般"。如果整组看不出明显差别，就明确说"无明显差别"，**不要硬排**。

## 任务

下面是 {n} 个针对同一个建站需求生成的网页全页截图，编号 0 到 {n_max}（顺序随机，与质量无关）。

请你以**整体审美观感**为主要依据，回答三个问题：
1. 哪几张**明显比组内其他的更好**？（可以是 0 张、1 张或多张）
2. 哪几张**明显比组内其他的更差**？（可以是 0 张、1 张或多张）
3. 如果全组水平接近、挑不出明显好坏，就直接判定"无明显差别"。

建站需求（仅用于理解这是个什么页面、给视觉判断提供上下文，**不评需求实现度**）：
{query}

## 怎么判"明显"

- "明显"的标准是：**一个普通人把这几张并排看一眼，不用细想就能指出来**。需要反复对比、放大细看才能分出高下的，不算明显。
- 好坏都是**相对组内**而言，不看绝对水平：
  - 即使这一组单独看都没有质量特别高的，但有一张明显比其他的要好一些，也可以把它选进 good。
  - 反之，这一组质量都挺好，但有一两张稍逊一筹、且明显能看出来的，也可以把它们选进 bad。
- 宁可少选、不要多选。选出的每一张都应该能用一句话说清"为什么它明显比其他的好 / 差"。
- **不要为了凑数把中游的选进 good 或 bad**。

## 整体审美观感看什么

凭整体直觉：这个页面像不像一个成熟设计师做出来的成品？是否有统一的视觉语言、舒服的配色、清晰的层级、精致的素材、恰当的留白？看完第一反应是"这做得真好看"，还是"能用但普通"，还是"这很糟"。

不要逐项打勾算分。但在组内比较时，下面这些**客观上公认的问题**是重要的参考：同组里带这些问题的页面，相对没有这些问题的页面更可能落到"明显差"。

**渲染 / 结构类**
- 白屏、纯色空白页、只有骨架 / 灰框 / loading 状态、内容没渲染出来
- 页面大面积截断：图片、卡片、mockup、图表的边缘被切掉，尤其深色背景上的截断
- 板块之间夹着大段无内容的纯色空带；某个区块一半有内容、一半空着
- 元素互相重叠、文字压在图上看不清、内容溢出容器、明显错位

**素材类**
- 用简陋 / 画崩 / 比例失调的 SVG 涂鸦冒充图片（人物五官走形、物体变形、剪贴画感）
- 占位符图片：灰框、破图、多张一模一样的占位 SVG 重复排列
- 把通用图标（放大镜、星星、箭头）放得极大当主视觉，空洞廉价
- 整页几乎没有任何视觉素材，只有文字 + 细线框，像文档站 / 线框稿

**文字 / 配色类**
- 文字不可读：对比度过低、字压在复杂背景上、字号失控
- 配色刺眼冲突，或通篇单调死板（大片纯黑 / 纯白 / 纯灰，没有任何色彩层次）

"明显好"则完全是主观感受：如果这一组里有哪一个页面相比其他的**明显让你眼前一亮**——特别有艺术感、设计感，或者特别酷炫——那它就是"明显好"。没有这种感觉，就不要选。

## 注意

- 编号是匿名候选，不要推测来源。
- 不判断内容是否正确、功能是否可用、需求是否实现——那些由其他评审负责。
- 多张页面如果几乎一样（同一模板、只是细节不同），它们应该同进同出，不要拆开。

## 输出格式

仅输出 JSON，不要 markdown：
{
  "reason": "先一句话说全组整体水平，再逐一说明每张被选进 good / bad 的理由（≤ 150 字）",
  "good": [明显更好的编号列表，可为空],
  "bad": [明显更差的编号列表，可为空],
  "no_clear_difference": false
}

约束：good 与 bad 不能有交集；no_clear_difference 为 true 时 good 和 bad 必须都为空；不必覆盖所有编号，未列出的即为"一般"。
